# لینک سفارش (MVP)

نسخهٔ نمایشی راه‌حل «لینک سفارش» برای چالش ریشه‌یابی.
مسئله: فروشندهٔ خانگی اینستاگرام سفارش، واریز، آدرس و سابقهٔ مشتری را فقط در دایرکت نگه می‌دارد و گم می‌کند.

## چه کاری می‌کند

| صفحه | کاربر | کار |
|---|---|---|
| `/` | فروشنده | جدول مشتریان. مشخصات مشتری (نام، آیدی اینستاگرام، موبایل، شهر، آدرس، یادداشت) در خود جدول ویرایش می‌شود. ستون‌های سفارش (تعداد، جمع خرید، وضعیت) فقط‌خواندنی‌اند. |
| `/` ← «سفارش جدید» | فروشنده | برای مشتری سفارش می‌سازد و لینکش را کپی می‌کند. دکمهٔ «همان قبلی» اقلام آخرین سفارش را پر می‌کند. |
| `/` ← «سفارش‌ها» | فروشنده | جدول سفارش‌های همان مشتری. بعد از پرداخت می‌تواند فایل پیوست کند و کد رهگیری ثبت کند. |
| `/o/[id]` | مشتری | وضعیت سفارش را می‌بیند و «پرداخت» را می‌زند. بعد از ارسال، کد رهگیری را همین‌جا می‌بیند. |

سفارش پرداخت‌شده‌ای که بیش از ۴۸ ساعت ارسال نشده با برچسب «عقب‌افتاده» مشخص می‌شود. این همان سنجهٔ اصلی گزارش است.

## ساده‌سازی‌های این نسخه

این نسخه فقط جریان کار را نشان می‌دهد. نسخهٔ واقعی این‌ها را لازم دارد:

- **ورود فروشنده.** صفحهٔ اصلی الان برای همه باز است. در نسخهٔ واقعی فروشنده باید وارد شود و فقط مشتریان خودش را ببیند.
- **پایگاه داده.** داده‌ها از یک فایل JSON ثابت (`src/data/seed.json`) خوانده می‌شوند و تغییرات در `localStorage` همان مرورگر می‌مانند. پس سفارشی که در یک مرورگر ساخته شود در مرورگر یا دستگاه دیگر دیده نمی‌شود. لینک سفارش‌های نمونه در همهٔ مرورگرها باز می‌شود، ولی تغییر وضعیتشان محلی است.
- **درگاه پرداخت.** دکمهٔ «پرداخت» فقط وضعیت را عوض می‌کند. در نسخهٔ واقعی مشتری به درگاهی مثل زرین‌پال می‌رود و سفارش فقط بعد از تأیید تراکنش در سمت سرور «پرداخت‌شده» می‌شود.
- **پیامک.** ارسال خودکار کد رهگیری به مشتری پیاده نشده است؛ مشتری کد را در صفحهٔ لینک می‌بیند.
- **افزودن مشتری.** مشتری جدید از داخل برنامه ساخته نمی‌شود؛ فهرست مشتری‌ها از فایل نمونه می‌آید.
- **فایل پیوست.** فایل به‌صورت data URL در `localStorage` می‌ماند و سقف ۳۰۰ کیلوبایت دارد. نسخهٔ واقعی فضای ذخیره‌سازی فایل می‌خواهد.
- **فرم مشتری.** در طرح اصلی مشتری خودش محصول و آدرس را در فرم وارد می‌کند. اینجا فروشنده سفارش را می‌سازد تا جریان کوتاه بماند.

## اجرا

```bash
pnpm install
pnpm dev
```

```bash
pnpm test
```

## اجرا با داکر

```bash
docker compose up -d --build
```

برنامه روی پورت `3020` سرور بالا می‌آید (داخل کانتینر `3000`). در Nginx Proxy Manager یک Proxy Host برای `mvp.solop.ir` بسازید که به `IP سرور:3020` برود.

## ساختار

- `src/lib/domain.ts`: قواعد سفارش (ساخت، پرداخت، پیوست، ارسال، عقب‌افتادگی). بدون وابستگی به React و با تست در `domain.test.ts`.
- `src/lib/store.ts`: لایهٔ ذخیره‌سازی نمایشی (`seed.json` به‌علاوهٔ `localStorage`). در نسخهٔ واقعی فقط همین فایل با فراخوانی API عوض می‌شود.
- `src/components/data-grid/`: دیتاگرید [tablecn](https://github.com/sadmann7/tablecn). دو تغییر کوچک در آن داده‌ام: گزینهٔ `meta.readOnly` برای قفل کردن یک ستون (`data-grid-row.tsx` و `types/data-grid.ts`) و پنهان شدن ردیف «Add row» وقتی افزودن ردیف فعال نیست (`data-grid.tsx`).
